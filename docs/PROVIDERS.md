# Provider Contracts

This matrix describes the current implementation, not everything each vendor offers. Reviewed on **2026-11-14** against the official sources below. The adapters have **offline, fake-Transport contract tests**. A dated metadata smoke check also fetched OpenRouter's anonymous public catalog through the guarded transport on 2026-11-14; that established catalog reachability only. No provider credentials or live inference were used. `ready` means that the listed protocol is implemented, not that a particular account, model, region, or inference API has been live-verified.

ModelPort uses direct HTTP contracts through an injected, guarded transport. It does not install vendor SDKs, inherit SDK retries, download provider media URLs, or guess OpenAI compatibility from a vendor name.

## Verification Semantics

| State | Evidence | Does not establish |
| --- | --- | --- |
| `authenticated` | A documented protected metadata or identity endpoint accepted the supplied credential. Response-specific rejection flags are checked. | Inference success, model entitlement, credits, spending limits, future availability, or free metadata. |
| `reachable` | A public metadata endpoint or a local endpoint responded with the expected catalog contract. | Whether authentication is enabled or the supplied credential was actually checked. |
| `unverified` | No reviewed credential-only probe is implemented for that profile. | Any credential validity claim. |

`inferenceTested` is always `false` in a verification result, including after a run. Verification and catalog listing never generate text, images, speech, transcriptions, or embeddings. Cohere's **bodyless POST `/v1/check-api-key`** is a documented credential-inspection exception to GET-only metadata handling; it is not inference. Connecting or refreshing can perform both verification and catalog requests. Metadata is not represented as guaranteed free merely because it uses GET.

An explicit user-supplied key is required for every ready cloud profile, even when its catalog is public. Keys are sent only in the listed headers, never in query parameters or JSON/multipart bodies. OpenRouter, Hugging Face, Deepgram, and ElevenLabs catalog-only requests omit the credential entirely. Identity details, key labels, quotas, provider error bodies, and other raw response extras are not returned by the adapters.

The Together host is intentionally `api.together.ai`, as shown in the current official authentication guide. Its Python SDK still declares `api.together.xyz`; the older SDK host is not used as a retry or redirect fallback. If either a provider's endpoint or its documented envelope changes, the adapter fails explicitly rather than treating an incompatible response as successful verification.

ElevenLabs is intentionally conservative: the general authentication guide says requests need `xi-api-key`, while the detailed `/models` reference provides unauthenticated examples and no required auth field. The catalog-only probe uses the detailed headerless contract. A successful headerless catalog is only reachability, never credential acceptance; if the service instead requires auth, it fails clearly rather than upgrading the result or silently retrying with a key. No additional account-identity endpoint or broader key scope is requested.

## Native Request Contracts

| Provider / operation | Request | Normalized result |
| --- | --- | --- |
| OpenAI / text or vision | POST `/chat/completions`, one user message, `stream: false`. Legacy chat uses the approved `max_tokens`; reviewed `gpt-5`/`o1`/`o3`/`o4` families use `max_completion_tokens`. Vision is an inline `data:` image content part. | Assistant text and numeric token counts only. |
| OpenAI / image | POST `/images/generations`, one `1024x1024` image, `output_format: png`, `stream: false`, no `response_format` for reviewed GPT Image IDs listed below. Legacy DALL-E serialization uses `response_format: b64_json` only for explicitly declared IDs; retired models are not auto-enabled. Other model IDs are rejected until a request profile is reviewed. | `b64_json` only; PNG/JPEG signatures required. URL-only results fail. No returned media URL is ever fetched. |
| OpenAI or Groq / stt | POST `/audio/transcriptions`, multipart with model, `response_format: json`, raw uploaded bytes, a cryptographically random boundary, and a fixed filename based on an allowlisted MIME type. | The transcription `text`, including an empty transcript for silence. |
| OpenAI / tts | POST `/audio/speech`, model, input text, approved voice, `response_format: mp3`. | Inline `audio/mpeg`. The SDK supplies OpenAI's declared default voice `alloy` before approval if no voice was chosen. |
| OpenAI, Mistral, or local compatible / embedding | POST `/embeddings`, one text input, `encoding_format: float`. | A finite numeric vector, never base64-encoded embeddings or arbitrary response metadata. |
| Anthropic / text or vision | POST `/messages`, approved `max_tokens`, `stream: false`, text blocks and optional `image` block with `source.type: base64`. | Text blocks and token counts only; no thinking/tool blocks are executed or returned. |
| Gemini / text or vision | POST `/models/{id}:generateContent`, `contents[].parts`, optional `inlineData`, approved `generationConfig.maxOutputTokens`, `candidateCount: 1`, `responseModalities: [TEXT]`. | Non-thought text parts from the first candidate and token counts. No text output or a safety-blocked response fails explicitly. |
| Gemini / embedding | POST `/models/{id}:embedContent`, model resource and one text content part. | `embedding.values`. Arbitrary resource paths/URLs are rejected. |
| Cohere / text | POST `/v2/chat`, messages, approved `max_tokens`, `stream: false`. | `message.content` text blocks and `usage.tokens`. |
| Cohere / embedding | POST `/v2/embed`, `texts: [text]`, `input_type: search_document`, `embedding_types: [float]`, `truncate: NONE`. | `embeddings.float[0]`. Query/document embedding roles are not interchangeable; this contract chooses document input explicitly. |
| Ollama / text or vision | POST `/api/chat`, `stream: false`, approved `options.num_predict`, optional raw base64 `messages[].images`. | `message.content` and evaluation token counts. |
| Ollama / embedding | POST `/api/embed`, input text, `truncate: false`. | `embeddings[0]`. |
| ElevenLabs / tts | POST `/text-to-speech/{voice_id}?output_format=mp3_44100_128`, `{text, model_id}`, `xi-api-key`. | Inline `audio/mpeg`; no implicit voice lookup or cloning. |
| Deepgram / stt | POST `/listen?model={canonical_name}`, raw audio bytes and allowlisted audio Content-Type, `Authorization: Token`. No callback, URL upload, summary, sentiment, or extra inference options. | The first alternative transcript from each returned channel. No word, confidence, account, or media metadata is copied. |

Other compatible cloud profiles call their documented `/chat/completions` only, with inline image content parts where their operation list permits vision. There are no tools, client retries, model fallbacks, streaming responses, background jobs, or additional generation requests. Router services still own their internal routing and billing behavior; ModelPort does not promise control over undisclosed provider-internal work.

Reviewed current GPT Image IDs are `gpt-image-1-mini`, `gpt-image-1.5`, `gpt-image-2`, `gpt-image-2-2026-04-21`, `gpt-image-2.5-sunburst`, `gpt-image-2.5-sunburst-2026-09-08`, `gpt-image-2.5-flare`, `gpt-image-2.5-flare-2026-09-08`, `gpt-image-2.6-sunburst`, `gpt-image-2.6-flare`, and `chatgpt-image-latest`. The current reference says `gpt-image-1` shut down on 2026-10-23 and describes DALL-E response-format parameters as legacy/retired. These old IDs receive no automatic image capability. Legacy request serialization is contract-tested for explicitly declared IDs but is **not** a claim that a retired model still works. GIF, SVG authoring, edits, partial images, and extra author-model calls are not currently supported.

All text/vision requests require the cap supplied by the SDK-approved input. A cap is not an enforceable dollar budget. Missing model-specific support can produce an upstream rejection; an adapter never silently removes an unsupported parameter and retries.

## Capabilities And Bounds

- `provider`: reviewed fields in the actual catalog, such as Anthropic image-input support/token limits, Mistral flags, DeepSeek/OpenRouter/HF input and output modalities, Cohere endpoints, ElevenLabs TTS support, or Deepgram batch support.
- `reference`: a small exact model-ID reference in `adapters.ts`, applied only to a model actually returned by the catalog. It is not a claim of entitlement, deployment, or current availability. When a result combines reference and provider evidence, the whole model is conservatively labeled `reference`.
- `unknown`: missing or insufficient metadata with no exact reference. `operations` is empty. There is no universal text/vision fallback, substring model-name matching, GGUF filename guessing, or inference probe.
- `declared`: explicitly supplied by the human through the SDK. A declaration cannot enable an operation outside the provider profile, replace a missing native protocol, or bypass approval.

Capabilities are intersected with the adapter's implemented operations. Explicit negative metadata takes precedence over a reference. Retired/inactive catalog entries and OpenAI entries past their `shutdown_date` are not enabled; deprecated entries and announced shutdown dates produce a warning. Catalog metadata is not a price quote or a model-access guarantee.

Anthropic, Gemini, and Cohere pagination is bounded to **10 pages and 1,000 inspected entries**, requesting 100 entries per page. Other catalogs are also capped at 1,000 entries. Repeated, malformed, oversized, or credential-reflecting cursors stop pagination with a truncation warning; provider-supplied pagination URLs are never followed. Duplicate model IDs are deduplicated. Invalid identifiers are omitted with a warning. Missing endpoints and empty catalogs require manual model declaration, not a fabricated default model.

Metadata requests ask the transport for a 4 MiB response limit and a 30-second timeout; inference asks for at most 16 MiB and 120 seconds. The shared transport applies its own hard limits, pins vetted DNS addresses, blocks redirects, and rejects private destinations except an explicitly allowed exact loopback endpoint. Local overrides use SDK-normalized literal loopback addresses/ports and the profile's API base path. Only local requests set `allowLoopback`. Cloud base URL overrides are never used by an adapter.

Inputs are SDK-validated inline base64, not remote URLs. Multipart filenames and media types cannot inject headers. Returned media remains inline; the shared SDK separately checks output signatures and image dimension bounds. HTTP 401/403/429 and network/timeout errors become sanitized `ModelPortError` codes/statuses without upstream bodies, keys, URLs, or exception causes. A timeout or size rejection does not cancel work already accepted upstream and is never automatically retried.

## Extending A Profile

Add or broaden a registry entry only with official evidence for the exact auth headers, read-only probe, catalog envelope, operation route, and request/response formats. Keep uncertain credential checks unverified. Add provider-specific dispatch rather than assuming a shared `/audio`, `/images`, or `/embeddings` route. Update model capability provenance, negative/unknown cases, and bounded pagination. Add fake-Transport tests for the operation, key isolation, sanitized failures, and the absence of extra requests before changing the matrix. Enterprise jobs, server-side tools, URL media, or new auth flows require a separate review, not just another provider name.
